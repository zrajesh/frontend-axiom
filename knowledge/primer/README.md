# Primer — reference material, not house decisions

These seventeen documents were the original knowledge base. Six ablations then
measured what they actually add to a capable model: **~zero**. Token storage,
SSR-for-SEO, single-flight refresh, consent gating, virtualization — a strong
model already meets every one of these unprompted, whether or not this plugin
is installed.

They are kept rather than deleted for two reasons.

**They measurably help smaller models.** On a 3-file repo the haiku control
forked the design system in every run; with this material it composed what
already existed (+0.25). That effect is real and grows as cheaper models get
deployed more widely.

**They are the reference behind `../house.md`.** When that file says 170 KB or
"risk-weighted coverage", the reasoning lives here.

What is *not* here is anything arbitrary. Every house choice moved to
`../house.md`, which is injected directly into context rather than linked —
because a path is a suggestion and injected text is not.

Nothing in this folder is routed to a capable model by default.
