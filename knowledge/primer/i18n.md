# Internationalization Standards

Retrofitting i18n is one of the most expensive refactors in frontend work, because hardcoded strings and Anglocentric layout assumptions spread into every component. Decide early whether the product will ever ship in a second locale — if the answer is "probably", build for it now.

## Never concatenate translated strings

```js
// Wrong — word order is not universal, and plurals aren't a suffix
`You have ` + count + ` new ` + (count === 1 ? "message" : "messages")

// Right — one message, one key, the library decides
t("inbox.unread", { count })
```

Concatenation bakes English grammar into code. Many languages order clauses differently, and plural rules vary by language — Arabic has six plural categories, Polish three, Japanese one. Use **ICU MessageFormat** (`{count, plural, one {...} other {...}}`) and let the formatter decide.

The same applies to rich text: use ICU tags or a component interpolation API rather than splicing JSX around translated fragments.

## Keys

- Semantic, namespaced keys — `cart.empty.title`, not `emptyCart1` and not the English sentence as the key.
- English-as-key breaks the moment the English copy is edited for tone, silently un-translating every locale.
- One namespace per feature, colocated with the feature (`principles.md` §8).
- Never build keys dynamically (`t('status.' + s)`) — it defeats static extraction and unused-key detection, so missing translations surface in production instead of CI.

## Formatting

Use `Intl` — never hand-format. The two that actually bite:

- **`Intl.Collator` for sorting anything user-visible.** Default `Array.sort()` is codepoint order, which misplaces every accented character. This ships constantly and looks like a data bug.
- **Store and send UTC (ISO 8601); format at the edge in the user's timezone.** Never send a pre-formatted date from the server — it cannot be re-localized.

`NumberFormat`, `DateTimeFormat`, `RelativeTimeFormat`, `ListFormat` as usual.

## Layout

- **RTL is a first-class case.** Use CSS logical properties — `margin-inline-start`, not `margin-left`; `padding-block`, not `padding-top`. They flip automatically under `dir="rtl"`.
- Set `dir` and `lang` on `<html>`. `lang` also drives screen-reader pronunciation (`accessibility.md`).
- **Design for text expansion.** German and Finnish routinely run 30–40% longer than English; fixed-width buttons and single-line truncation break first. Test with the longest locale, not the shortest.
- Mirror directional icons (back arrows, progress) under RTL; don't mirror logos or media controls.

## Routing and SEO

- Locale in the URL — `/de/produkte` or a locale subdomain. Never switch language on a cookie alone: the content becomes uncacheable per-URL and unindexable (`seo-ai-seo.md`, `caching.md`).
- `hreflang` on every localized page, reciprocal across all locales, plus `x-default` for the selector or fallback.
- Localized sitemaps listing each locale variant.
- Translate `<title>`, `<meta description>`, and Open Graph tags — not just body copy.
- Never auto-redirect on `Accept-Language` alone. Offer the choice, remember it, keep the requested URL reachable — silent redirects break shared links and stop crawlers seeing other locales.

## Loading translations

- Ship only the active locale's messages. Bundling every locale is a common and significant bundle regression (`performance.md`).
- Server-render the first paint's strings. A flash of untranslated keys (`cart.empty.title`) is worse than a spinner.
- Missing-key behavior: fall back to the default locale and **report it** (`observability.md`). Rendering a raw key in production means nobody noticed.

## Review checklist

- [ ] No concatenated or interpolated sentence fragments
- [ ] Plurals via ICU, not ternaries
- [ ] All numbers/dates/lists/sorting via `Intl`
- [ ] Logical CSS properties; verified under `dir="rtl"`
- [ ] Layout survives ~40% text expansion
- [ ] `hreflang` reciprocal + `x-default`; localized metadata
- [ ] Only the active locale's messages in the bundle
- [ ] Missing keys fall back *and* report
